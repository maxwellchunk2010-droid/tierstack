How we rank

Scores come from tests, not sponsors. Every rule below is published so you can check our work — and challenge it.

Current status: Editorial v0 — hands-on testing in progress. Until a category's same-task tests are published, its tiers are labelled editorial, never presented as tested.

The 6 criteria (out of 100)

Score maps to tier: S is 85+, A is 75–84, B is 60–74, C is below 60. A named human reviewer may move a tool by one tier at most, and must write down why.

Same-task testing

Every tool in a category runs the same task, with the same published prompts. Coding agents add auth + a CRUD page to a starter Next.js repo, fix 3 seeded bugs, and build a small browser game from one prompt. App builders build the same waitlist page + admin dashboard with a database. Agent tools build the same form-to-notification workflow. Game-dev tools generate the same prop and import it into Unity or Godot.

Every test produces a public test log: date, version or model, prompts, outputs, and the score sheet. Claims about a tool are tied to a dated log — nothing vaguer than that gets published.

Retest cadence

Patch Notes are reviewed daily. Tier lists are reviewed monthly. A major release — new model, big feature, or price change — triggers a retest within 7 days.

Stale badge

Every page shows its last-tested date. Any tool not tested in 90 days gets a visible Stale badge automatically, so old rankings never quietly pretend to be current.

Paying never changes rank

Paying never gets a tool ranked and never moves it up. Money can only buy clearly labelled visibility (for example a marked Sponsored slot, visually separate from the tier list). We publish who paid, and correct errors publicly with a changelog.

How new tools get in

Discovery or a community tip puts a tool on the Watchlist. A real product with public signup, real users, and active development moves it to Queued for test. After the hands-on test it is ranked or rejected — and both results are public.
